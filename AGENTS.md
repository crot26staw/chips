# Овощные чипсы

Одностраничный лендинг на русском языке. Сначала разрабатываем и согласуем статическую версию на HTML, CSS и JavaScript. Следующий этап — интеграция этой верстки в WordPress.

## Текущее состояние

Десктопная главная «Хрустящий перекус» сверстана целиком. В версии для просмотра доступны девять секций, меню, переходы «Купить» к выбору магазина, оба телефона и почта. Исходный десктопный фрейм `20878:20080` имеет размер 1440 × 7544 px. [Макет в Figma](https://www.figma.com/design/DbzU9GW0nMBAKXXLAVDAye/?node-id=20878-20080)

Перед подключением продаж нужны URL интернет-магазина, трёх карточек на маркетплейсах и сообщества ВКонтакте. В Figma эти адреса отсутствуют. После получения адресов замените четыре кнопки `.shop-buy` на ссылки с тем же оформлением, подключите ссылку в подвале и обновите пояснение «Скоро здесь появятся прямые ссылки…». В шапке и в подвале указаны разные телефоны — оба перенесены из макета. Отдельные мобильные композиции и тема WordPress относятся к следующим этапам.

## Как проверять верстку по макету

Работайте сверху вниз. После изменения блока отрендерите его в браузере и наложите на соответствующий участок экспорта Figma. При ширине 1440 px и масштабе браузера 100% один пиксель макета равен одному CSS-пикселю. Для сравнения снимков выставьте DPR 1, включите сокращение движения и дождитесь `document.fonts.ready` и загрузки изображений. В шапке и секции с картофелем учитывайте наложенные поверх фреймов элементы.

## Масштабирование PxToRem

Базовый фрейм — 1440 px, при этой ширине контента `1rem = 16px`. Начиная с планшетной ширины 768 px корневой размер шрифта равен доступной ширине страницы, умноженной на `16 / 1440`. В `main.js` наблюдатель передаёт в CSS ширину за вычетом системной полосы прокрутки и обновляет её при изменении окна. На более узких экранах используется масштаб планшета до разработки мобильной композиции.

Размер из Figma делите на 16. Например, отступ 32 px записывается как `2rem`. Когда важно сохранить в CSS исходное число из макета, используйте `padding: calc(32 * var(--design-px))`. Высоты секций, шрифты, отступы и смещение вступительной анимации следуют одному масштабу. Для изображений с `srcset` выражайте ширину слота в `sizes` как долю ширины страницы. Например, упаковка шириной 327 px занимает `22.70833vw` от планшета и выше.

Проверены ширины от 768 до 3840 px. У всех девяти секций отклонение от пропорциональной геометрии составило менее 1 CSS-пикселя, горизонтального скролла не было. При ширине 1440 px полноразмерный скриншот после изменения масштаба попиксельно совпал с предыдущей версией. Проверены загрузка фотографий, переходы меню и CTA с Lenis и с сокращением движения, а также открытие страницы без JavaScript.

## Как запустить проект

Для работы с другого аккаунта владелец добавляет разработчика в **Settings → Collaborators**, а разработчик принимает приглашение. [Репозиторий на GitHub](https://github.com/crot26staw/vegetable-chips)

На новом компьютере клонируйте проект и перейдите в его папку.

```sh
git clone https://github.com/crot26staw/vegetable-chips.git
cd vegetable-chips
```

Пока десктопная верстка проходит ревью, после клонирования переключитесь на неё командой `git switch feature/desktop-landing`. После слияния используйте `main`. [Pull request с версткой](https://github.com/crot26staw/vegetable-chips/pull/1)

Откройте `index.html` прямо в браузере или запустите из корня проекта локальный сервер с Python 3.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте в браузере `http://127.0.0.1:8000/`. Сервер останавливается сочетанием Ctrl+C. Все зависимости уже включены в репозиторий, установка пакетов и сборка для запуска не требуются.

## Где вносить изменения

| Файл или каталог | Назначение |
| --- | --- |
| `index.html` | Семантическая разметка, текст и порядок секций |
| `assets/css/main.css` | Стили страницы и адаптивная верстка |
| `assets/images/` | Иллюстрации, фотографии и фирменная графика из Figma. В `cutouts/` лежат варианты овощей и упаковок для обычных и плотных экранов |
| `assets/fonts/` | Локальные шрифты Onest, Oswald и Wix Madefor Display с лицензиями. Надпись «Онлайн» экспортирована из текстового слоя Gilroy в SVG |
| `assets/js/main.js` | Инициализация прокрутки и анимаций |
| `assets/vendor/` | Готовые файлы библиотек из npm-пакетов `gsap` и `lenis` |

Размещайте контент в HTML, используйте относительные пути к ресурсам. Для анимаций помечайте элементы атрибутами `data-*`, чтобы изменения классов оформления не затрагивали поведение.

GSAP и Lenis загружаются перед `main.js` с атрибутом `defer`. Один цикл `gsap.ticker` передаёт время в `lenis.raf()`. При включённом сокращении движения браузер использует обычную прокрутку. При обновлении зависимостей берите файлы из каталога `dist/` соответствующего npm-пакета, сохраняйте лицензионные уведомления и обновляйте версии в этом документе. [Интеграция Lenis с GSAP](https://github.com/darkroomengineering/lenis#gsap-scrolltrigger) · [GSAP ticker](https://gsap.com/docs/v3/GSAP/gsap.ticker/)

## Совместная работа

Основная ветка — `main`. Перед началом задачи проверьте `git status`. Если рабочая копия чистая, обновите `main` и создайте ветку под задачу. Выберите короткое название, описывающее новую задачу.

```sh
git switch main
git pull --ff-only
git switch -c feature/update-shop-links
```

После правок проверьте изменённые секции при ширине фрейма, прокрутку, переходы меню, консоль браузера и режим сокращённого движения.

Зафиксируйте относящиеся к задаче файлы, отправьте ветку командой `git push -u origin HEAD` и откройте pull request в `main`. При передаче незавершённой работы укажите ветку или ссылку на pull request, обновите раздел «Текущее состояние» и запишите, что проверено и с чего продолжать.

## Перенос в WordPress

После согласования статической страницы сохраните ссылку на её коммит для сверки. Уточните тип темы и какие тексты, изображения и повторяющиеся элементы заказчик будет менять через админку.

Для классической темы перенесите разметку главной в `front-page.php`, а общие части — в `header.php` и `footer.php`. Подключите CSS и JS через `wp_enqueue_scripts` в `functions.php`, указав GSAP и Lenis зависимостями основного скрипта. Формируйте пути к файлам темы через `get_theme_file_uri()`. Сохраните классы, атрибуты анимаций и якоря при замене статического контента на поля WordPress. Сверьте результат с согласованным коммитом на тех же ширинах экрана. [Подключение ресурсов в теме WordPress](https://developer.wordpress.org/themes/core-concepts/including-assets/)
