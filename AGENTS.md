# Овощные чипсы

Одностраничный лендинг на русском языке. Сначала разрабатываем и согласуем статическую версию на HTML, CSS и JavaScript. Следующий этап — интеграция этой верстки в WordPress.

## Текущее состояние

Главная «Хрустящий перекус» сверстана для телефона, планшета и десктопа. Все три версии используют одну разметку девяти секций. На планшете меню открывается кнопкой в шапке, карточки вкусов и магазинов выстраиваются в колонку, фотография «В школу» расположена над текстом. На телефоне меняются кадрирование фотографий, размер шапки, компоновка карточек и подвала. Кнопки «Купить» ведут к выбору магазина. [Десктопный макет 1440 × 7544](https://www.figma.com/design/DbzU9GW0nMBAKXXLAVDAye/?node-id=20878-20080) · [Планшетный макет 768 × 9670](https://www.figma.com/design/DbzU9GW0nMBAKXXLAVDAye/?node-id=20903-2836) · [Мобильный макет 375 × 7902](https://www.figma.com/design/DbzU9GW0nMBAKXXLAVDAye/?node-id=20878-20172)

Перед подключением продаж нужны URL интернет-магазина, трёх карточек на маркетплейсах и сообщества ВКонтакте. В Figma эти адреса отсутствуют. После получения адресов замените четыре кнопки `.shop-buy` на ссылки с тем же оформлением, подключите ссылку в подвале и обновите пояснение «Скоро здесь появятся прямые ссылки…». В шапке и в подвале указаны разные телефоны — оба перенесены из макета. После согласования адаптивной верстки следующий этап — тема WordPress.

## Как проверять верстку по макету

Работайте сверху вниз. После изменения блока отрендерите его в браузере и наложите на соответствующий участок экспорта Figma. Выставьте ширину контента 375 px для телефона, 768 px для планшета или 1440 px для десктопа. Установите масштаб браузера 100%. При этих настройках один пиксель макета равен одному CSS-пикселю. Для сравнения снимков выставьте DPR 1, включите сокращение движения и дождитесь `document.fonts.ready` и загрузки изображений. В шапке и секции с картофелем учитывайте наложенные поверх фреймов элементы.

## Масштабирование PxToRem

При ширине окна меньше 768 px действует мобильный макет с базой 375. От 768 до 1024 px включительно действует планшетный макет с базой 768. Выше 1024 px действует десктопный с базой 1440. Мобильные стили подключены после планшетных и переопределяют их только ниже 768 px.

На исходной ширине каждого фрейма `1rem = 16px`. Размер из Figma делите на 16. Например, отступ 32 px записывается как `2rem`. Также можно записать `padding: calc(32 * var(--design-px))`. Между контрольными ширинами корневой размер шрифта равен ширине контента, умноженной на 16 и делённой на базовую ширину активного макета. Наблюдатель в `main.js` передаёт ширину за вычетом системной полосы прокрутки. В `sizes` указывайте ширину слота в соответствующей композиции. Например, упаковка на планшете занимает 220 из 768 px, то есть 28,64583% ширины, а на десктопе — 327 из 1440 px.

Планшетную композицию проверили в Chromium на ширинах 768, 800, 820, 834, 900 и 1024 px, в том числе при DPR 2 и с эмуляцией сенсорного устройства. Десктопную проверили при 1025, 1280, 1440 и 1920 px. На этих ширинах все девять секций поместились без горизонтальной прокрутки. Их высоты отклонялись от пропорционального масштаба менее чем на 0,2 CSS-пикселя. При 1440 px скриншот попиксельно совпал с десктопной версией до добавления планшета.

Мобильную композицию проверили в Chromium на ширинах 320, 360, 375, 390, 414, 430, 540, 667 и 767 px с плотностью экрана от 1× до 3×. Высоты секций отклонились от пропорций макета менее чем на 0,35 CSS-пикселя. В WebKit с эмуляцией iPhone проверили загрузку графики, ширину страницы и переход из сенсорного меню на ширинах 320, 375, 390, 430, 767 и 768 px. В обеих проверках страница поместилась по ширине окна. Снимки 768 и 1440 px попиксельно совпали с версией до добавления мобильной верстки.

Проверьте раскрытие меню с клавиатуры, закрытие по Escape и клику снаружи, а также выбор каждого якоря. При переходе через 1024 px состояние меню сбрасывается. Без JavaScript ссылки меню доступны сразу. Переходы из меню и обеих кнопок «Купить» проверены с Lenis и с включённым сокращением движения.

## Как запустить проект

Для работы с другого аккаунта владелец добавляет разработчика в **Settings → Collaborators**, а разработчик принимает приглашение. [Репозиторий на GitHub](https://github.com/crot26staw/vegetable-chips)

На новом компьютере клонируйте проект и перейдите в его папку.

```sh
git clone https://github.com/crot26staw/vegetable-chips.git
cd vegetable-chips
```

Пока верстка проходит ревью, после клонирования переключитесь на неё командой `git switch feature/desktop-landing`. После слияния используйте `main`. [Pull request с версткой](https://github.com/crot26staw/vegetable-chips/pull/1)

Откройте `index.html` прямо в браузере или запустите из корня проекта локальный сервер с Python 3.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте в браузере `http://127.0.0.1:8000/`. Сервер останавливается сочетанием Ctrl+C. Все зависимости уже включены в репозиторий, установка пакетов и сборка для запуска не требуются.

## Где вносить изменения

| Файл или каталог | Назначение |
| --- | --- |
| `index.html` | Семантическая разметка, текст и порядок секций |
| `assets/css/main.css` | Общие стили, десктопная композиция и базовая формула PxToRem |
| `assets/css/tablet.css` | Планшетная композиция. Файл подключён после основного CSS с условием `(max-width: 1024px)` |
| `assets/css/mobile.css` | Мобильная композиция и база PxToRem 375. Подключается с условием `(width < 768px)` |
| `assets/images/` | Иллюстрации, фотографии и фирменная графика из Figma. В `cutouts/` лежат варианты овощей и упаковок для обычных и плотных экранов. В `tablet/` и `mobile/` находятся варианты графики для соответствующих макетов |
| `assets/fonts/` | Локальные шрифты Onest, Oswald и Wix Madefor Display с лицензиями. Надпись «Онлайн» экспортирована из текстового слоя Gilroy в SVG |
| `assets/js/main.js` | Расчёт ширины контента, управление меню, инициализация прокрутки и анимаций |
| `assets/vendor/` | Готовые файлы библиотек из npm-пакетов `gsap` и `lenis` |

Размещайте контент в HTML, используйте относительные пути к ресурсам. Для анимаций помечайте элементы атрибутами `data-*`, чтобы изменения классов оформления не затрагивали поведение.

GSAP и Lenis загружаются перед `main.js` с атрибутом `defer`. Один цикл `gsap.ticker` передаёт время в `lenis.raf()`. При включённом сокращении движения браузер использует обычную прокрутку. При обновлении зависимостей берите файлы из каталога `dist/` соответствующего npm-пакета, сохраняйте лицензионные уведомления и обновляйте версии в этом документе. [Интеграция Lenis с GSAP](https://github.com/darkroomengineering/lenis#gsap-scrolltrigger) · [GSAP ticker](https://gsap.com/docs/v3/GSAP/gsap.ticker/)

## Совместная работа

Основная ветка — `main`. Перед началом задачи проверьте `git status`. Если рабочая копия чистая, обновите `main` и создайте ветку под задачу. Выберите короткое название, описывающее новую задачу.

```sh
git switch main
git pull --ff-only
git switch -c feature/update-shop-links
```

После правок проверьте изменённые секции при ширине фрейма, прокрутку, переходы меню, консоль браузера и режим сокращённого движения.

Зафиксируйте относящиеся к задаче файлы, отправьте ветку командой `git push -u origin HEAD` и откройте pull request в `main`. При передаче незавершённой работы укажите ветку или ссылку на pull request, обновите раздел «Текущее состояние» и запишите, что проверено и с чего продолжать.

## Перенос в WordPress

После согласования статической страницы сохраните ссылку на её коммит для сверки. Уточните тип темы и какие тексты, изображения и повторяющиеся элементы заказчик будет менять через админку.

Для классической темы перенесите разметку главной в `front-page.php`, а общие части — в `header.php` и `footer.php`. Подключите CSS и JS через `wp_enqueue_scripts` в `functions.php`, указав GSAP и Lenis зависимостями основного скрипта. Подключите `tablet.css` после `main.css` с аргументом `$media` равным `(max-width: 1024px)`. Затем подключите `mobile.css` с условием `(width < 768px)`. Сохраните порядок элементов `<source>` в `<picture>`, чтобы на телефоне браузер первым выбрал мобильный вариант. Формируйте пути к файлам темы через `get_theme_file_uri()`. Сохраните классы, атрибуты анимаций и якоря при замене статического контента на поля WordPress. Сверьте результат с согласованным коммитом на тех же ширинах экрана. [Подключение ресурсов в теме WordPress](https://developer.wordpress.org/themes/core-concepts/including-assets/)
